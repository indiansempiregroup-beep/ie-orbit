# M11.7 — Self-Service Business Onboarding

## Overview

M11.7 enables new customers to provision an AppointIE workspace without administrator intervention.

Provisioning chain:

```
Public marketing → Registration wizard → Auth register → Tenant create → Business create → Settings patch → Dashboard
```

## Frontend surfaces

| Surface | Route | Module |
|---------|-------|--------|
| Public home | `/` | `web/src/features/public/HomePage.tsx` |
| Registration wizard | `/auth/register/start` | `web/src/features/onboarding/RegisterWizard.tsx` |
| Sign in | `/auth` | `web/src/features/auth/AuthPage.tsx` |
| Forgot / reset password | `/auth/forgot-password`, `/auth/reset-password` | `web/src/features/auth/*` |
| Email verification | `/auth/verify-email` | `web/src/features/auth/VerifyEmailPage.tsx` |
| Success | `/onboarding/success` | `web/src/features/onboarding/OnboardingSuccess.tsx` |
| Getting started | Dashboard sidebar | `web/src/features/onboarding/GettingStartedChecklist.tsx` |

## Reusable modules

- `web/src/config/onboarding.ts` — wizard steps, currencies, timezones, checklist items
- `web/src/features/onboarding/schemas/registerWizardSchema.ts` — Zod validation
- `web/src/features/onboarding/hooks/useOnboardingDraft.ts` — localStorage draft auto-save
- `web/src/features/onboarding/provisionWorkspace.ts` — client-side provisioning orchestration
- `web/src/lib/currency.ts` — `formatMoney()` without hardcoded INR

## SDK usage

All API calls use `@ie-orbit/sdk` via `createAuthenticatedClient()`:

- `auth.register`, `auth.login`, `auth.forgotPassword`, `auth.resetPassword`, `auth.verifyEmail`, `auth.resendVerification`
- `tenants.create`, `tenants.settings`
- `businesses.create`, `businesses.patch`

## Integration status (backend)

Completed in the rollout:

1. `POST /auth/register-business` now provides atomic business/workspace provisioning.
2. `GET /tenants/check-slug?slug=` is available for slug pre-check.
3. Product subscription foundations and billing hooks are wired.

Deferred:

1. Logo upload during onboarding (branding step) remains a future enhancement.

## Developer guide

### Run locally

```bash
pnpm --dir web dev
```

### Validate

```bash
pnpm --dir web build
pnpm --dir web lint
```

### Manual test flow

1. Open `/auth/register/start`
2. Complete all wizard steps (draft auto-saves to `localStorage`)
3. Submit review → workspace provisions
4. Land on `/onboarding/success` → open dashboard
5. Confirm getting-started checklist, workspace card, and currency on KPIs

### Form persistence

Draft key: `ie:onboarding:register-draft`  
Welcome flag: `ie:onboarding:show-welcome`  
Checklist progress: `ie:onboarding:getting-started`

## Billing foundation

Billing is now operationally scaffolded with Razorpay-ready workflows:

- Status endpoint: `GET /billing/status`
- Checkout: `POST /billing/checkout` (mock-safe when keys are absent)
- Webhooks: `POST /billing/webhooks/razorpay`
- Operations endpoints for events, summary, single/bulk reprocess

The UI still supports safe pre-go-live operation in mock mode until live credentials are configured.

## Accessibility

- Wizard stepper uses `aria-current="step"` and progressbar semantics
- Auth forms use labels, `role="alert"` for errors, and keyboard-navigable controls
- Public pages set `document.title` and meta description via `usePageMeta`

## Performance

- Route-level code splitting with `React.lazy` in `App.tsx`
- Wizard draft debounced auto-save (400ms)
- Provision step shows explicit loading state
